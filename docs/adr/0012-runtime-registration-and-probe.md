# Runtime registration fields and probe

Study OS locks **runtime registration** as learner state in the **student-model store**, keyed by **technology family** (v1: `sql`) — not per pack, not one global binary for every subject, and not in `~/.study-os/config.yaml`. v1 record fields: `family`, `engine` (closed set sized for Databases: `mysql`, `sqlite3`, `psql`), `command` (PATH name or absolute path). No DSN/host/password fields. Unknown `engine` is treated as unregistered. **Probe** means: resolve `command` and run a cheap version/help check; success allows live practice; failure falls back to **workspace artifacts** (+ suggest), with in-session re-probe after the learner says it is ready. Rejected: open string engines (tool-matrix creep), connection/login probes in v1, and storing registration only in harness config.
