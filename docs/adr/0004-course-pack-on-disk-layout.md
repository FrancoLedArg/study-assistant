# Course pack on-disk layout

Study OS locks a local **course pack** as `course-packs/<pack-id>/` in the workspace (bootstrap “active course pack” = that id). Required: `pack.yaml` (YAML; `display_name` required; machine id = folder name) and a `sources/` directory (may be empty) for **cátedra sources** — free tree, discovered by walk; optional `sources/index.yaml` annotations (`title`, free-string `kind`, `topics`) keyed by relative path. Optional `teaching/` (free yaml/md; recommended `teaching/config.yaml`) holds course-specific teaching config, separate from the learner **teaching profile**. Optional root `mastery.yaml` holds course mastery/KC *definitions* only; learner mastery *state* stays in the **student-model store**. Rejected: whole-workspace-as-one-pack, path-only packs like the store pointer, mandatory per-file manifest listing, teaching config only outside the pack, and putting learner state in the pack. Multi-pack physically = sibling dirs under `course-packs/`; selection UX is not locked here.
