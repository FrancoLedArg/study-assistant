# Multi-pack selection and switching

Study OS locks v1 **active course pack** selection as learner state in the **student-model store** (not harness config YAML). Packs are discovered by scanning workspace `course-packs/*/` directories that contain `pack.yaml` (id = folder name; label = `display_name`) — no separate registry. Switching is **between tutor loops only**, via harness tools that list packs and set the active pack id (skill-choreographed when the learner asks or bootstrap is unset); no separate GUI product. If the stored id is missing/invalid: auto-select and persist when exactly one valid pack exists; if zero or many without a valid selection, require an explicit learner choice before cátedra teaching — never invent a pack id. Rejected: mid-loop switches, hand-edit-only flows, silent default among many packs, and treating workspace config as the durable source of truth for active pack.
