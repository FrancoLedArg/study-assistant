# v1 mastery / gaps schema

Study OS locks course-tied mastery as a **flat overlay** of pack-authored **knowledge components**: each pack’s optional `mastery.yaml` defines units (`id`, `label`, required short `description`); learner state in the **student-model store** is `pack_id → { kc_id → score }` with scores on **0.0–1.0**, **absent until first evidence**, updated only via **validated proposals** that may raise or lower and may reference **only listed ids**. **Gaps** are not a separate store (low/missing scores + live tutor-loop diagnosis). No durable misconception facet, no prerequisite/knowledge-graph edges, no locked “mastered ≥ x” threshold, and no Databases KC catalog in this decision — pack content is authored later. Empty/missing `mastery.yaml` means no mastery proposals for that pack. Informed by ITS primary sources (`docs/research/its-learner-models.md`) but deliberately smaller than BKT/knowledge-space models.
