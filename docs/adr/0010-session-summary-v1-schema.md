# v1 session-summary schema

Study OS locks the **session summary** as mandatory structured residue of every **tutor loop** in the local **student-model store**. v1 fields: `id`, `started_at`, `ended_at`, active course-pack id, short session goal(s), short outcome, workspace-artifact paths touched, ids of validated proposals and evidence briefs from that loop, and optional short notes. Evidence briefs and proposal bodies remain **sibling** records (linked by id), not embedded. No chat transcript and no dump of the full teaching profile or mastery map. The next tutor loop loads the current student model plus the latest summary for the active pack (optionally up to a few recent summaries). Exact character caps and serialization spelling are implementation defaults, not this lock. Rejected: transcript-as-summary, inlining brief/proposal bodies, skipping summaries when no proposal was emitted, and treating summaries as the source of truth for scores.
