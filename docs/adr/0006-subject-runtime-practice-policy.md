# Subject-runtime vs artifact practice policy

Study OS locks a **harness-global** practice policy: **workspace artifacts** are the guaranteed path (a missing runtime never blocks the tutor loop); a live **subject runtime** is optional and used only when the learner’s **runtime registration** is present. The harness does not install or provision runtimes — the tutor should **suggest** install when live practice would help, then **re-check in-session** if the learner says it is ready. Course packs may declare a **technology preference** (e.g. Databases → MySQL, another pack → SQLite) for suggestion/default only; they cannot require a runtime or disable artifact fallback. Registration lives with the learner (student-model store / harness-facing config), not in the pack; when preference and registration disagree, **registration wins**. Rejected: artifacts-only forever (no opportunistic live use), harness install/setup flows, pack-required tools, and a global open-ended detect/tool matrix as a shape pillar. Exact binary names and registration key schema are left to implementation / later tickets.
