# v1 evidence-brief schema

Study OS stores an **evidence brief** only when the agent emits a **validated proposal** — exactly one brief per proposal, as a sibling record of the **session summary** in the local **student-model store** (linked by `session_id` / `proposal_id`), not embedded in the summary and not a chat transcript. The brief’s body is a small list of structured **moments** (`kind` + short interpretive `note` + optional learner-only `quote`); it does not copy the proposal delta, mastery/dim target, or artifact paths. v1 closed kinds: `struggle`, `preference_signal`, `success_with_style`, `misalignment`, `explicit_request`. Hard size caps keep it brief (≤3 moments; ≤~500 chars total notes; ≤~200 chars per quote), loosenable after testing. Rejected alternatives: always-on conversation highlights, briefs only after accept, many briefs per proposal, free-prose or quote-only bodies, embedding inside the session summary.
